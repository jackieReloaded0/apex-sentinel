Oracle Cloud Free Tier の Autonomous Database (Oracle APEX) は、約7日間の無通信で自動休眠・停止される制約があります。 本システムは、外部から定期的にヘルスチェックを行い稼働を維持（Keep-Alive）するとともに、直近の稼働メトリクスを収集・可視化する管理ダッシュボードです。

System Architecture

システムアーキテクチャ図

Cloud Scheduler による定期自動監視と、Web からの即時手動チェックを兼ね備えた 2 系統のハイブリッド監視アーキテクチャです。 

flowchart LR
    subgraph Trigger["定期トリガー"]
        CS["⏱️ Cloud Scheduler
(毎日 09:00 JST)"]
    end

    subgraph Batch["監視バッチ"]
        CRJ["⚡ Cloud Run Jobs
(Django Batch Worker)"]
    end

    subgraph Target["監視対象"]
        APEX["🏛️ Oracle APEX
(Autonomous DB)"]
    end

    subgraph DataStores["データストア群 (Polyglot Persistence)"]
        FS[("🔥 Cloud Firestore
(時系列ログ: NoSQL)")]
        NEON[("🐘 Neon PostgreSQL
(管理情報・認証: RDB)")]
    end

    subgraph Web["Web ダッシュボード"]
        CRS["🌐 Cloud Run Service
(Django Web App)"]
    end

    %% 1. 定期バッチフロー
    CS -->|"自動起動"| CRJ
    CRJ -->|"定期 Ping (HTTP GET)"| APEX
    APEX -->|"200 OK (ms)"| CRJ
    CRJ -->|"時系列ログ追記"| FS

    %% 2. 手動オンデマンド監視フロー
    CRS -->|"⚡ 手動 Ping (HTTP GET)"| APEX
    CRS -->|"即時ログ追記"| FS

    %% 3. Web 表示フロー
    CRS -->|"ログ取得・可視化"| FS
    CRS -->|"セッション・認証管理"| NEON

Cloud Scheduler が Cloud Run Jobs を毎日 09:00 に起動し、Oracle APEX の生存維持（7日休眠制約回避）と時系列ログ記録を行う自動バッチフローです。

    APEX -->|"ステータス (200 OK) & 応答時間 (ms)"| CRJ

管理画面上のボタン押下を契機に、Web サーバーから直接 Oracle APEX へ Ping を送信して即時検証（0.2秒応答）し、Firestore へ記録するオンデマンド監視フローです。
